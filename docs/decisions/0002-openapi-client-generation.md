# 0002 — Generate the Angular API client from a build-time OpenAPI document

**Status:** accepted · Phase 0

## Context

The spec requires the Angular client to be generated by NSwag from the .NET
OpenAPI document, never hand-written, and regenerated by an npm script. NSwag
needs an OpenAPI document as input. Two ways to get one: run the API and fetch
`/openapi/v1.json` at runtime, or emit it at build time.

## Decision

Enable **build-time OpenAPI emission** via
`Microsoft.Extensions.ApiDescription.Server` (`OpenApiGenerateDocumentsOnBuild`),
which writes `src/Hirepath.Api/Hirepath.Api.json` on every `dotnet build`. NSwag
(`nswag.json`) reads that file and emits the Angular client to
`src/Hirepath.Web/src/app/core/api/`. The npm script `generate:api` runs NSwag.

Both the emitted `Hirepath.Api.json` and the generated client are git-ignored.
The hand-written DI wiring (`core/api.providers.ts`) is committed.

## Consequences

- Client generation is offline and deterministic — no need to boot the API or
  manage a dev certificate just to regenerate types.
- The flow is: `dotnet build` (emits JSON) → `npm run generate:api` (emits TS).
  `run`/`verify` scripts and CI orchestrate this order.
- Endpoints use `TypedResults.Ok<T>` so response schemas appear in the document
  and the generated client is strongly typed.
