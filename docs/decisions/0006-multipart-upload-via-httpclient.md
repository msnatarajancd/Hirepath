# 0006 — Resume upload posts via HttpClient, not the generated client

**Status:** accepted · Phase 1

## Context

The Angular client is generated by NSwag from the .NET OpenAPI document and is
used for every operation. The one exception is the multipart resume upload:
across several OpenAPI shapes (`IFormFile` parameter, a `[FromForm]` model, a
schema transformer marking the file `format: binary`), NSwag either dropped the
file parameter or generated a URL-encoded body and never emitted the
`FileParameter` type it referenced.

## Decision

- Post the single multipart upload directly with Angular `HttpClient`
  (`FormData`) in `ResumeStore`. It is a few lines, standard, and reliable.
- Keep everything else on the generated client.
- Add a tiny committed ambient declaration (`core/api-shims.d.ts`) for
  `FileParameter` so the generated client still type-checks; its unused upload
  method is harmless.

## Consequences

- Uploads work reliably and the rest of the app stays fully generated.
- If a future NSwag/.NET combination generates a correct file upload, delete the
  shim and the direct-post and switch back — revisit then.
- The endpoint itself is unchanged and covered by an API integration test.
